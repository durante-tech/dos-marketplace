## Overview

DOS retires things weekly — packs, skills, hooks, tools, versions, adopted imports — and every
one of those decisions has so far been made from convention: the `.retired/` directory, the
tombstone pattern, strangler-fig successions, ad-hoc ledger rows. This skill codifies that
practice into checkable workflows, built on one premise: **a capability is a liability that must
keep earning its keep**, and removal done well is a shipped deliverable with the same evidence
standard as an addition — replacement first, dependents migrated, citations resolving, rollback
anchored.

Subtraction counts as evolution. A clean retirement is a successful generation.

Routing edge: SunsetImport is Retire specialized for capabilities with an upstream — it adds
trigger re-verification and attribution preservation, then delegates mechanics to Retire.

## Doctrine (the four laws every workflow enforces)

1. **Keep-test before touch.** Five questions answered with evidence — field use, uniqueness,
   dependents, replacement, ownership — recorded where the work is ledgered. A capability that
   passes stays; retirement proceeds only on a named failure.
2. **Replacement-first.** No compulsory removal without a working successor, and the remover
   migrates the dependents — a deprecation announced and abandoned is not a deprecation, it is
   debt with a banner.
3. **Closure is checkable (RFC-0092 standard).** After removal, every surviving reference to the
   retired name resolves — to the tombstone or the successor. Generated surfaces (indexes,
   catalogs, counts) are regenerated by their generators, never hand-edited.
4. **Rollback before removal.** The anchor (tag + restorable backup) exists and is verified
   BEFORE the removing change ships. An untested rollback path means the removal does not land.

```

  CONVERT-TO-POINTER / RE-ADOPT, mirrors the adoption ledger entry
→ User gets a verdict row with attribution preserved either way
```
