Single source of truth for all tier-keyed values. Adding a tier = one row edit.

| Tier | E-flag | Budget | ISC Floor | Min Capabilities | Max Parallel Agents | Advisor Default | When |
|------|--------|--------|-----------|------------------|---------------------|-----------------|------|
| Standard | E1 | <2min | 8 | 1-2 | 3 | — | Normal request (DEFAULT) |
| Extended | E2 | <8min | 16 | 3-5 | 5 | — | Quality must be extraordinary |
| Advanced | E3 | <16min | 24 | 4-7 | 8 | — | Substantial multi-file work |
| Deep | E4 | <32min | 40 | 6-10 | 12 | — | Complex design |
| XHigh | — | <60min | 50 | 7-12 | 15 | AUTO at PLAN+LEARN | Opus 4.7 sweet spot (API `/effort xhigh`) |

**Triggers:** `/e[1-5]` or `E[1-5]` as a standalone token in the principal's message (case-insensitive). When detected:

2. Add `effort_source: explicit` to PRD frontmatter

4. E1 forces fast-path mode IF task structure satisfies §1.3 WHITELIST

### §1.2 — Task Profile Classifier

Run BEFORE voice + PRD edit. Output `📋 PROFILE:` line stating the choice. Compresses ceremony for non-strategic tasks while preserving verifiability.

| Profile | Phase Sequence | When |
|---------|----------------|------|
| read-only / audit / discovery | OBSERVE → EXECUTE-as-investigation → VERIFY → LEARN | No file writes, only reports findings. INTEL-FIRST + MEMORY RECALL still fire. |
| trivial mechanical | OBSERVE → BUILD → VERIFY → LEARN | Single file, <3 lines, no logic change (typo, version bump, env var) |
| deterministic workflow | OBSERVE-light → BUILD → EXECUTE → VERIFY → LEARN | "Run skill X with default workflow" (DOSUpgrade, Sentinel scan, Compliance) |
| standard / multi-file / strategic | Full 7-phase ceremony | Default — anything not above |

### §1.3 — Walking Skeleton (Fast-Path WHITELIST)

**The introductory path through the Algorithm.** A new contributor learns the WHITELIST first; the 7-phase ceremony is the explicit escalation. Available at **Standard tier (E1) only**, on tasks satisfying ALL conditions:

- Effort tier is E1 (auto-detected or explicit `/e1`)
- Task is one of: rename a symbol, fix a typo, run a command, read-and-report-on a file, append a single line, format/lint, single-package install, single test run
- Single file or single command in scope
- No multi-step transformation
- No new architecture, no new endpoints, no new dependencies, no migrations

**If ALL conditions hold** → set `mode: fast-path` in PRD frontmatter (still write the stub for telemetry). Compress to: OBSERVE → EXECUTE → VERIFY (skip THINK / PLAN / BUILD / LEARN).

**If ANY condition fails** → fast-path does NOT apply. Proceed with standard 7-phase Algorithm.

**Whitelist rationale:** any heuristic-shaped bypass becomes a doctrine-evasion route under tier time pressure. Explicit enumeration closes the loophole.

## §2 — PRD as System of Record

**The AI writes ALL PRD content directly using Write/Edit tools.** PRD.md in `MEMORY/WORK/{slug}/` is the single source of truth. The AI is the sole writer — no hooks, no indirection.

**What the AI writes directly:**
- YAML frontmatter (task, slug, effort, phase, progress, mode, started, updated; optional: iteration, effort_source)
- All prose sections (Context, Criteria, Decisions, Verification)
- Criteria checkboxes (`- [ ] ISC-1: text` / `- [x] ISC-1: text`)
- Progress counter (`progress: 3/8`)
- Phase transitions (`phase: execute`)

**What hooks do (read-only from PRD):** PRDSync.hook.ts fires on Write/Edit of PRD.md and syncs frontmatter + criteria to `work.json` for the dashboard. **Hooks never write to PRD.md — they only read it.**

prd.recordDecision(text) → appends to ## Decisions

Adapter handles YAML serialization; doctrine references the port by name. **Not implemented today.** This section names the target for a future sub-doc lift.

## §3 — ISC Decomposition

**The core principle: each ISC criterion = one atomic verifiable thing.** If a criterion can fail in two independent ways, it's two criteria. A PRD with 8 fat criteria is worse than one with 40 atomic criteria — fat criteria hide unverified sub-requirements.

**Anti-criteria** (ISC-A prefix): what must NOT happen.

### §3.1 — Splitting Test

Apply to EVERY criterion before finalizing:

1. **"And" / "With" test** — contains "and", "with", "including", "plus" joining verifiable things → split
2. **Independent failure test** — can part A pass while part B fails? → separate criteria
3. **Scope word test** — "all", "every", "complete", "full" → enumerate. "All tests pass" for 4 test files = 4 criteria, one per file
4. **Domain boundary test** — crosses UI/API/data/logic? → one criterion per boundary

### §3.2 — Decomposition by Domain

| Domain | Decompose per... | Example |
|--------|-----------------|---------|
| UI/Visual | Element, state, breakpoint | "Hero section visible" + "Hero text readable at 320px" + "Hero CTA clickable" |
| Data/API | Field, validation rule, error case, edge | "Name field max 100 chars" + "Name field rejects empty" + "Name field trims whitespace" |
| Logic/Flow | Branch, transition, boundary | "Login succeeds with valid creds" + "Login fails wrong password" + "Login locks after 5 attempts" |
| Content | Section, format, tone | "Intro present" + "Intro under 50 words" + "Intro uses active voice" |
| Infrastructure | Service, config, permission | "Worker deployed" + "Worker has R2 binding" + "Worker rate-limited 100 req/s" |

### §3.3 — ISC Count Gate

**Cannot exit OBSERVE with fewer ISCs than the TierConfig floor (§0).**

If count < floor: re-read each criterion, apply the Splitting Test, decompose, rewrite the PRD's Criteria section, recount. Repeat until floor met. Gate exists because [R-counts-50] showed 0 of 10 Extended PRDs hit the 16-minimum and the single Deep PRD had 11 vs 40-80.

### §3.4 — 3-Column ISC Template

When refining criteria, capture for each:
- (a) **Pass criterion** — verifiable end-state, 8-12 words
- (b) **Anti-criterion** — out-of-scope work that's tempting but wrong
- (c) **Verification method** — which command, file, or artifact proves it

If every reasonable execution would pass the criterion as written, rewrite — Splitting Test failure mode = "passes trivially on write".

## §4 — Capability Invocation Contract

**THE RULE (single canonical statement — referenced from every phase below):**

> Selecting a capability creates a binding commitment to call it via tool. Every selected capability MUST be invoked during BUILD or EXECUTE via `Skill` tool call (for skills) or `Task` / `Agent` tool call (for agents). Writing text that resembles a skill's output does NOT count as invocation. Selecting a capability and never calling it via tool is a **CRITICAL FAILURE** — dishonest. If you realize mid-execution a capability isn't needed, remove it from the selected list with a reason rather than leaving a phantom selection.

VERIFY (§6.6) confirms this rule by parsing the PRD's `🏹 CAPABILITIES SELECTED` against the tool-use ledger.

## §6 — The 7 Phases

Standard ceremony. Profile-compressed sequences (§1.2) skip phases per the table; remaining phases retain full structure.

### §6.1 — OBSERVE  ━ 1/7

**Trigger:** Algorithm entry OR re-entry after compaction recovery.

**Inputs:** principal's message, prior-session digests (if any), entity subjects.

**Procedure:** Phase Entry Ritual (§5). Then in parallel where independent:

#### a. INTEL-FIRST (mandatory whenever subject is a person, company, domain, email, or external entity)

- **Trigger** — task subject is an entity (always-fire, NOT conditional on WebFetch). Skip silently ONLY when subject is a non-entity (config key, file path, abstract concept).
- **Procedure** — run `bun ~/Durante/Tools/intel-context.ts <subject> --format json` ONCE, BEFORE forming the plan and BEFORE any other entity-related tool calls. CLI fans out to 7 internal surfaces in parallel: MemPalace KG, MemPalace drawer, Studio `/api/v1/relationships/notes`, Studio `/api/v1/sessions`, MEMORY/RESEARCH grep, MEMORY/RELATIONSHIP grep, MEMORY/ARTIFACTS grep.
- **Audit surface** — surface the CLI's `summary_md` field VERBATIM as `🔍 INTEL PRE-FLIGHT:` in OBSERVE output. Hand-rolled equivalents (ad-hoc Grep, individual MCP calls, ChiefOfStaff/ContextSearch) are NOT substitutes — they bypass the unified-port audit Sentinel R14 verifies. The CLI is the canonical single first call.
- **Exit codes** — `0` = completed (any hits, proceed) | `2` = all 7 surfaces failed (escalate via AskUserQuestion before any external research) | `3` = subject malformed (fix and retry).
- **Reflection provenance** — [R-mcvey-2026-04-29], [R-fresh-session-2026-05-03].

#### b. MEMORY RECALL (mandatory, parallel with Reverse Engineering)

Extract task-relevant entities from the principal's prompt. Run `bun ~/Durante/Tools/intel-context.ts <entity> --surfaces kg,drawer,research --format json` per entity. CLI queries KG + drawer + research vault in parallel; `INTEL_CACHE_TTL` (§0). Surface as `🧠 PRIOR CONTEXT:` bullets. Fall back to `uv run --with mempalace python ~/.claude/DOS/Tools/mempalace_bridge.py kg_query <entity>` if intel-context unavailable. State "no prior context found" if empty. Skip silently only when all surfaces error. [R-kg-only-misses-9]

#### c. PRIOR-SESSION RECOVERY

Query the two session-continuity predicates (both registered in PREDICATES.md §1.8):
```bash
uv run --with mempalace python ~/.claude/DOS/Tools/mempalace_bridge.py kg_query_predicate '{"predicate":"compacted_with_digest"}'
uv run --with mempalace python ~/.claude/DOS/Tools/mempalace_bridge.py kg_query_predicate '{"predicate":"stopped_with_digest"}'
```
If either returns current facts, surface most-recent digest drawer ID as `🧠 PRIOR SESSION:`, then read the drawer via `mempalace_get_drawer` before forming the plan. Skip silently on bridge error or no facts.

#### d. LINEAGE SUGGESTION HOOK (mandatory when creating new PRD, opt-in per project)

Bridge call (RFC-0010 §9):
```bash
uv run --with mempalace python ~/.claude/DOS/Tools/mempalace_bridge.py suggest_parent \
  '{"task": "<task text>", "require_projects_file": true, "limit": 1}'
```
Bridge gates on `.dos-projects.json` presence (Tools/ canonical, root fallback). Projects without the file get `{gated: true, reason: "no-projects-file"}` and the hook silently no-ops. When `candidates[0]` returned, emit ONE italic line at TOP of OBSERVE output (before `🔎 REVERSE ENGINEERING`):

```
*Possibly related: <artifactId> (<title>) — confidence <N.NN>.
Run `bun ~/Durante/Tools/lineage.ts link <prd-slug> --to <artifactId>` to confirm.*
```

**Non-blocking invariants** (RFC-0010 §9.2):
- MUST NOT prompt for confirmation
- MUST NOT block phase transition
- MUST NOT write `parent:` (only explicit `dos lineage link`)
- MUST silently skip on `gated: true`, `count: 0`, or bridge error
- MUST emit AT MOST ONE italic line per OBSERVE

Bridge default `min_confidence` is `LINEAGE_MIN_CONFIDENCE` (§0). RFC-0010 §9.3's aspirational 0.8 does not apply to Durante — embeddings calibration differs.

#### e. SOURCE-BEFORE-SUMMARY (mandatory if task touches existing files OR will spawn sub-agents that touch them)

Parent algorithm READS those files first (parallel batch) BEFORE forming detailed plans or spawning sub-agents. Sub-agents receive ground-truth file content as context, not summary-of-summary. Add `### Ground Truth Files Read` subsection to PRD `## Context` listing files-read-as-source. [R-fabrication-8]

#### e2. DISCOVERY-FIRST CHECKPOINT (mandatory when task involves new implementation work — Standard+)

Before authoring any new component (hook, skill, RFC, agent, policy, schema, doctrine section), probe in-tree for existing implementation. The slice-collapse pattern (RFC-0058 P1, P2) — 8/13 v0.0.8 ratifications closed via discovery-first probing rather than full engineering — earns its keep when applied mechanically rather than aspirationally.

**Procedure:**

1. **Enumerate** — list the components the task names ("redactor hook", "policy schema", "council motion", "Sentinel R-rule").
2. **Probe each** before scoping engineering work:
   - File presence: `ls ~/.claude/{hooks,agents,skills}/<plausible-name>*` and equivalents under `~/Durante/Packs/`, `~/Durante/Tools/`.
   - Symbol grep: `grep -rn "<distinctive-identifier>" ~/.claude ~/Durante/Tools ~/Durante/Packs ~/Durante/Plans` for type names, function exports, RFC IDs.
   - Binary inspection (when an external dep defines the surface): `strings <bin> | tr ';,' '\n\n' | grep "<expected-symbol>"`.
3. **Record** each probe outcome in PRD `## Context` → `### Discovery-First` subsection: `<component> | <probe command> | <hit | miss> | <slice-collapse decision: full | partial | none>`.
4. **Re-scope** based on findings:
   - ALL probes hit → task is verification + status promotion (slice-collapse). Re-scope tier downward; PRD reads as a verification PRD, not an engineering PRD.
   - ANY probe miss → full engineering scope on that subset only. Record what's missing AND what already exists; reuse via import rather than reauthor.

**Anti-pattern caught:** authoring a new hook from scratch when the parent hook already imports the catalog the new hook would reuse — discovery-first surfaces the import chain before duplicate authoring. Same shape catches duplicate RFCs, duplicate agent definitions, duplicate Sentinel R-rules.

**Output**: `🔎 DISCOVERY-FIRST:` line in OBSERVE console output enumerating each probe + outcome AND a populated `### Discovery-First` subsection in PRD `## Context`.

**Skip silently** only when task is read-only / report-only (no implementation), or when no new component is named.

[R-discovery-first-DOSUpgrade-theme-2 — frequency 5 in DOSUpgrade reflection sweep; lineage RFC-0058 P1 / P2 / v0.0.5 final-receipt lessons-inherited]

#### e3. CONSTRAINT-DISCOVERY CHECKPOINT (mandatory when task signals data migration — Standard+)

Before authoring a data-migration plan, inventory the database constraint surface — what FKs, NOT NULLs, CHECK constraints, unique indexes already exist. Skipping this is the recurring failure mode behind reflection theme #4 (frequency 5 in DOSUpgrade sweep): partial rollbacks, failed `prisma migrate dev`, schema-divergence regressions all trace back to running the migration before reading the constraint catalog.

**Trigger** — task body OR PRD `task` field matches: "data/schema migration", "prisma migrate", "alter table", "drop column", "drop table", "add column", "add constraint", "rename column".

**Procedure:**

1. **Read the constraint catalog** before forming the migration plan. Postgres: `SELECT conname, contype, conrelid::regclass FROM pg_constraint WHERE connamespace = 'public'::regnamespace`. SQLite: `PRAGMA foreign_key_list(<table>)` per touched table. Other engines: equivalent introspection.
2. **Record findings** as `## Pre-Migration Constraints` section in PRD `## Context` — list constraints by name + type + dependent table. Include FK graph if the migration touches multiple tables.
3. **Plan around** discovered constraints (cascade order, drop+recreate sequencing, deferrable vs immediate) BEFORE writing migration SQL. Front-loaded inventory replaces run-time discovery.

**Anti-pattern caught:** running `prisma migrate dev` to "see what breaks" — the breakage is the discovery, the cost is rollback. Constraint inventory is the cheaper place to spend the discipline.

**Output**: `🧱 PRE-MIGRATION CONSTRAINTS:` line in OBSERVE summarizing inventory size + populated `## Pre-Migration Constraints` PRD section. Sentinel R37 (`presence.migration-constraint-discovery`) audits at scan time.

**Skip silently** when task carries no migration signal. v0.0.10 Bucket B4 — DOSUpgrade reflection theme #4.

#### e4. SYMLINK-MODE PROBE (mandatory when task touches `~/.claude/` files)

If the task will edit anything under `~/.claude/`, run `readlink ~/.claude` once at OBSERVE. Surface as `🔗 SYMLINK MODE:` line.

**Two outcomes:**

- **Symlink** (e.g., `~/.claude → ~/Durante/Releases/v0.0.10/.claude`) — live install and the active submodule are the same physical inode. One write hits both. Four Copies effectively reduces to Three Copies. Maintainer pattern on Lucas's machine.
- **Plain directory** — live and submodule are independent. Multi-copy edits MUST sync via `bun ~/Durante/Tools/sync-check.ts --fix` before commit. Customer install pattern.

The probe takes ~1ms and prevents the "edited live but didn't sync to submodule" foot-gun (and its inverse). When in symlink mode the probe also reminds the operator that pack-source ↔ submodule still requires explicit sync — same-inode helps two surfaces, not all three.

**Skip silently** when task does not touch `.claude/` paths. v0.0.10 Bucket B5 — DOSUpgrade reflection theme #5.

**PRE-BATCH BUDGET CHECK (mandatory at PLAN→BUILD when launching a batch operation — i.e., when PARALLELISM Q1, Q2, or Q3 is "yes"):**

Before spawning a batch operation whose cost scales with N (parallel agents, `/batch` over N files, multi-file rewrite), explicitly compute the budget envelope. Skipping this is the recurring failure mode behind reflection theme #1 — front-loaded constraint inventory would have saved 8+ runs (frequency 6 in DOSUpgrade reflection sweep).

| Op type | Budget formula | Time cap (tier §0) | Count cap (tier §0) |
|---------|---------------|---------------------|---------------------|
| `Skill("batch", ...)` over N files | N × per-file-effort | tier budget × 1.0 | — (N is files, not agents) |
| `Agent` spawn × M parallel | M × per-agent-budget | tier budget × 1.0 | M ≤ Max Parallel Agents |
| Single-thread multi-file rewrite | N × per-file-effort | tier budget × 0.5 (single thread can't parallelize) | — |
| Mixed (some parallel + some serial) | sum of per-stream max | tier budget × 1.0 | M_parallel ≤ Max Parallel Agents |

Both caps must hold for `proceed` — exceeding either triggers tier-up or split-batches per the Decision rules.

**Decision rules:**

- **proceed** — projected ≤ ceiling × 0.8 (20% headroom). Batch fits within tier budget.
- **tier-up** — projected ∈ [ceiling × 0.8, ceiling × 1.5]. Escalate via `/e3`, `/e4`, or `/effort xhigh` BEFORE spawning. Document the bump in PRD `## Decisions`.
- **split-batches** — projected > ceiling × 1.5. Decompose into K sub-batches each fitting within tier; ship sub-batches sequentially. Document the split in PRD `## Decisions` with the partition rule.

Don't proceed with a batch that's already over-budget — `BUDGET_OVERRUN_TRIGGER` (§0) auto-compresses mid-execution at 150% and that compression loses fidelity. Pre-budget check is the cheaper place to spend the discipline.

## §7 — Critical Rules (Zero Exceptions)

### §7.1 — Mandatory Output Format
Every response MUST use one of CLAUDE.md's defined output formats (ALGORITHM / NATIVE / MINIMAL). No freeform output. Source: `~/.claude/CLAUDE.md` MODES section — this doctrine does not redefine.

### §7.2 — Response Format Before Questions
Always complete the current response format output FIRST, then invoke AskUserQuestion at the end. Show your work-in-progress (OBSERVE output, reverse engineering, effort, ISC, capability selection — whatever you've completed so far), THEN ask. Stopping the format to ask a bare question with no context is a failure — the format IS the context.

### §7.3 — Capability Invocation Contract
See §4 — single canonical statement. No phantom capabilities. Selection without tool call is a CRITICAL FAILURE.

### §7.4 — ISC Count Gate
See §3.3 — cannot exit OBSERVE with count < TierConfig (§0) floor for the chosen tier.

### §7.5 — Voice Curls — Primary Agent Only
Background agents, subagents, and teammates spawned via Task / Agent tool MUST NEVER make voice curl calls. Voice is exclusively for the main conversation agent. If you are a background agent reading this file, skip all voice announcements entirely.

### §7.6 — Atomic Criteria Only
Every criterion must pass the Splitting Test (§3.1). No compound criteria with "and" / "with" joining independent verifiables. No scope words ("all", "every") without enumeration.

### §7.7 — Context Compaction at Phase Transitions
At each phase boundary (Extended+ effort), if accumulated tool outputs and reasoning exceed `COMPACTION_THRESHOLD` (§0 — per-tier, monotonic: E2 compacts earliest at 40%, E5 latest at 60%; Standard exempt), self-summarize before proceeding. Preserve: ISC status (which passed/failed/pending), key results (numbers, decisions, code references), next actions. Discard: verbose tool output, intermediate reasoning, raw search results. Format: 1-3 paragraphs replacing prior phase content. Prevents context rot — the #1 cause of late-phase failures in long Algorithm runs. Inspired by RLM (Zhang/Kraska/Khattab 2025).

### §7.8 — PRD Is Your Responsibility
If you don't edit the PRD, it doesn't get updated. There is no hook safety net. Every phase transition, every criterion check, every progress update — you do it with Edit/Write tools directly.

### §7.9 — No Silent Stalls
Ensure no processes are hung — explore agents not returning, research agents not responding, etc. If an agent stalls, intervene; do not silently wait.

### §7.10 — Predicate Governance (BLOCK MODE)
Before referencing a new KG predicate in any doctrine prose or sub-doc, register it in `~/.claude/skills/MemPalace/PREDICATES.md` §1.x first. Doctrine that references an unregistered predicate is a doctrine violation — the predicate gate blocks the write.
