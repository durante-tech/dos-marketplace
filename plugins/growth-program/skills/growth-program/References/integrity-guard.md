# Integrity guard (cross-cutting, non-negotiable)

The program is only as trustworthy as its weakest stat. This is what kept `altyaa-turbo#251` honest
(its verify pass refuted 5 fabricated/misattributed figures). Lazy-loaded by the conductor + owned by
the **Skeptic** council seat.

## Stat integrity — adversarial verify
- Every load-bearing number (market size, competitor review counts, AI-citation percentages, traffic
  shares) gets an independent verify pass that tries to **refute** it against a primary source.
- Confirmed → keep with a source. Refuted/unverifiable → move to an explicit
  **`> DO NOT CITE — unverified`** block; it may inform intuition but must NEVER be load-bearing.
- Name the source inline. "A study found…" with no source is treated as fabricated.

## Review & schema integrity — legal hard rules
- **No fake or incentivized reviews.** FTC Consumer Review Rule + platform ToS (G2/Capterra delist for
  self-seeding). Review density is *earned*, never manufactured.
- **No `AggregateRating` / `Review` schema without verified, real data.** Emitting rating schema you
  can't substantiate is a structured-data violation and a trust risk.

## Sequencing integrity
- The reviews/corpus pillar is **arithmetically gated on a real paying-customer base** — surface that
  gate as a blocker; do not present review-seeding as a day-0 action.
- Distinguish **off-repo P0** (claim directory profiles, create entity graph) from in-repo schema work;
  don't let an easy in-repo sprint masquerade as the highest-leverage move.

## Locale integrity
- If the primary market is non-English, flag thin locale research as a **known gap** requiring a
  dedicated deep-research pass before committing locale budget — never extrapolate from EN data.
